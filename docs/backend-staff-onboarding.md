# Staff onboarding: what the backend needs

The telecalling dashboard has a **Staff onboarding** page (Team → Staff onboarding) where the
telecalling head adds telecallers and creates their **Staff ID** and **temporary password**.
Today these are saved only on the machine running this app (`.data/staff-accounts.json`,
passwords hashed with scrypt). For staff to actually sign in, `manikstu-backend` needs the
following.

## 1. Fields on `users`

| Column | Type | Notes |
|---|---|---|
| `staff_id` | string, unique | e.g. `MK-TC-120`; generated by the backend, next number after the highest |
| `mobile` | string, unique | 10-digit Indian mobile (the table already has `phone`; either reuse it or add a unique index) |
| `region` | string | already exists |
| `vertical_ids` | json | product lines the telecaller handles; no longer chosen in the form, defaults to `[1]` |
| `daily_call_target` | integer | 5–200 |
| `must_change_password` | boolean, default `false` | `true` whenever the head sets or resets the password |
| `details_shared_at`, `training_done_at` | timestamp, nullable | onboarding checklist |
| `created_by` | foreign key → users, nullable | who added the account |
| `password_reset_at`, `last_login_at` | timestamp, nullable | |

`is_active` already exists and is used for deactivate / activate.

## 2. A telecalling head role

The head currently signs in with `role = telecaller`. Add a separate role (e.g. `telecalling_head`),
or a permission, so only the head can manage staff and every telecaller keeps their own view.

## 3. Head-only endpoints

| Method | Path | Body | Does |
|---|---|---|---|
| GET | `/telecalling/staff` | | List staff (never return password hashes) |
| POST | `/telecalling/staff` | name, mobile, email, region, vertical_ids?, daily_call_target, password | Create a telecaller; returns the new `staff_id` |
| PATCH | `/telecalling/staff/{id}` | is_active?, details_shared?, training_done? | Deactivate / activate, tick onboarding steps |
| POST | `/telecalling/staff/{id}/password` | password | Set a new temporary password, `must_change_password = true` |

Validation should match the app: name 3–60 characters, valid mobile, email required (staff sign in
with it), unique mobile and email, password at least 8 characters with a letter and a number.
Hash passwords with Laravel's `Hash::make`.

## 4. Sign-in and first-login password change

- Allow signing in with **Staff ID** (and email / mobile) as well as email.
- Refuse sign-in when `is_active = false`.
- When `must_change_password` is true, return a flag so the client sends the user to a
  "set your own password" screen before anything else, and add an endpoint for it
  (`POST /auth/change-password`) that clears the flag.
- Record `last_login_at`.
- Rate-limit sign-in attempts.

## 5. Moving this app onto the backend

Replace `lib/staffAccounts.ts` (local file) with calls to the endpoints above; the Staff onboarding
page already talks to the app's own `/api/staff` routes, so only those routes need to change.
